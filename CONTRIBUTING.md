# Contributing to Aervellum

Thank you for helping improve Aervellum. Bug reports, documentation fixes, and
small focused pull requests are welcome.

## Before opening a pull request

1. Follow the setup instructions for your operating system in `README.md`.
2. Create a branch from `main`.
3. Keep models, recordings, transcripts, diary entries, compiled runtimes, and
   environment files out of Git.
4. Run the project checks:

   ```text
   npm run check
   npm run portability
   ```

5. Describe the operating system and transcription backend you tested.

Use a public issue for ordinary bugs and feature ideas. For anything that could
expose recordings, notes, local files, or private network access, follow
`SECURITY.md`.
